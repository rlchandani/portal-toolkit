# Phase 1 (v1.2 "Feels solid") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the v1.2 release: architecture cleanup (10a–10f), connection health + auto-reconnect (#7), device dashboard + power controls (#5), and dark theme (#9), with the repo's first test suite.

**Architecture:** Mechanical extraction of the 3,659-line `MainScreen.kt` into feature packages first, then Navigation-Compose, then a vendored ADB channel factory to eliminate reflection into dadb internals, then ViewModel split with a shared `ConnectionHolder`. New user-facing features (#7, #5, #9) build on the cleaned base.

**Tech Stack:** Kotlin, Jetpack Compose (BOM 2024.12.01), Material3, Navigation-Compose 2.8.x, DataStore 1.1.x, dadb 1.2.6, JUnit4 + kotlinx-coroutines-test.

## Global Constraints

- Portal devices are Android 10 / SDK 29; `PortalDeviceConfig.MAX_SDK = 29` must not change.
- All user-facing strings go in `values/strings.xml` (Romanian default) AND `values-en/strings.xml`.
- Immutable state: StateFlow updates create new data-class instances; never mutate.
- Conventional commits (`feat:`/`fix:`/`refactor:`/`chore:`/`test:`), no AI attribution.
- Every remote op surfaces errors via the existing `AdbError` hierarchy / `formatAdbReason`.
- Build verify command: `./gradlew assembleDebug` (must pass at every commit).
- Test command: `./gradlew testDebugUnitTest`.
- SDK path: `local.properties` → `sdk.dir=/opt/homebrew/share/android-commandlinetools` (do not commit local.properties).
