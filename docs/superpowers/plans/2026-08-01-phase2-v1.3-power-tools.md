# Phase 2 (v1.3) "Power tools" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Tools bottom-nav destination hosting a remote shell, a live logcat viewer, and screen capture/live-peek, built on the existing shared ADB connection.

**Architecture:** Each tool is a feature package (`ui/tools/shell`, `ui/tools/logcat`, `ui/tools/capture`) with its own ViewModel resolving deps from `AppContainer`, mirroring the Phase 1 ViewModel split. Streaming tools (logcat) use `Dadb.open()` from the vendored ADB channel; one-shot tools (shell, screencap) use `Dadb.shell()`/`pull()`. History/Settings move under Tools so the bottom nav stays at four tabs. Pure logic (logcat parsing, ring buffer, destructive-command classifier) is extracted into testable non-Android units.

**Tech Stack:** Kotlin, Jetpack Compose, Material3, TCA-free AndroidViewModel + StateFlow, DataStore, dadb (via `data/adb/DadbConnections`), kotlinx-coroutines.

```kotlin
package com.portalinstaller.data.tools

/**
 * Clasifică o comandă shell ca fiind distructivă (schimbă starea/pornirea
 * dispozitivului) pentru a cere confirmare înainte de rulare. Regulile sunt
 * conservatoare: preferăm un fals-pozitiv (o confirmare în plus) unei comenzi
 * distructive rulate din greșeală.
 */
object ShellCommandClassifier {
    private val DESTRUCTIVE = listOf(
        Regex("""\brm\b"""),
        Regex("""\breboot\b"""),
        Regex("""\bpm\s+(disable|uninstall|clear)\b"""),
        Regex("""\bsettings\s+put\b"""),
        Regex("""\bsvc\b"""),
        Regex("""\bkill\b|\bkillall\b""")
    )
    fun isDestructive(command: String): Boolean {
        val normalized = command.trim().lowercase()
        return DESTRUCTIVE.any { it.containsMatchIn(normalized) }
    }
}
```
