# Portal Toolkit v1.5 — Live Mirror & Control Design

**Goal:** Replace the ~1.5s PNG "peek" with a real-time, low-latency screen mirror of the Portal that you can also control (tap, swipe, long-press, hardware keys, text) directly from the phone — a focused "scrcpy-lite" feature. Plus a small honest fix on the Screensaver tab: a photo-count guidance hint.

**Architecture:** Two independent pipelines run over the single existing shared `Dadb` connection (ADB multiplexes logical streams, so no new connection is needed — already proven by `LogcatViewModel` streaming while the health monitor pings). A **video pipeline** opens a long-lived `screenrecord --output-format=h264 -` stream, feeds the raw H.264 bytes to a `MediaCodec` decoder rendering to a `Surface`. A **control pipeline** maps phone gestures/buttons to short-lived `input ...` shell commands sent to the Portal.

**Tech Stack:** Kotlin, Jetpack Compose (Material3), `dev.mobile:dadb` 1.2.10 (`AdbStream` + `okio.BufferedSource`), Android `MediaCodec` (async mode), `SurfaceView`/`AndroidView`.

## Feature 1 — Live Mirror & Control ("scrcpy-lite")

### Data flow

**Video (Portal -> phone):**
```
dadb.open("shell:screenrecord --output-format=h264 --time-limit=180 --size <WxH> -")
   -> AdbStream.source (raw H.264 bytes, okio.BufferedSource)
   -> MediaCodec (async) -> Surface -> Compose AndroidView(SurfaceView)
```
- One long-lived coroutine on `Dispatchers.IO` reads byte chunks and queues them into the decoder's input buffers.
- `screenrecord` enforces a hard limit (default 180s; we set `--time-limit=180` explicitly). When the stream ends, the manager transparently reopens it. UI shows at most a brief freeze, no user action.
- Device resolution comes from `wm size` (parsed once at start) and is used both for the `--size` cap and for coordinate mapping.

**Control (phone -> Portal):**
```
Compose gesture / button / text
   -> InputInjector maps view px -> device px
   -> dadb.shell("input tap|swipe|keyevent|text ...")  (fire-and-forget on IO)
```
- Each event is one short-lived `shell()` call (matches existing one-shot idiom). No stream held for control.

### Components (all new, small, focused)

**`data/tools/ScreenMirrorManager.kt`** (~120 lines)
- Responsibility: open/own the `screenrecord` H.264 `AdbStream`; expose a byte-chunk `Flow<ByteArray>` and the parsed device `Size`. Handle the 180s restart transparently.
- Consumes: `Dadb` (passed per call, like other managers).
- Produces:
  - `suspend fun deviceSize(dadb: Dadb): Size` — parses `wm size` output (`"Physical size: 1280x800"` -> `Size(1280, 800)`).
  - `fun stream(dadb: Dadb, size: Size): Flow<ByteArray>` — cold Flow; on collection opens `shell:screenrecord ... -`, emits `source.read(buffer)` chunks until cancelled; closes the `AdbStream` in `finally`. On normal end-of-stream (time-limit), re-opens within the same Flow (loop) so the collector sees a continuous byte stream.
- Errors: if `screenrecord` exits non-zero immediately (secure surface / unsupported), the Flow throws `MirrorUnsupportedException` for the VM to catch.

**`data/tools/H264Decoder.kt`** (~140 lines)
- Responsibility: wrap `MediaCodec` in async callback mode; accept H.264 byte chunks, render decoded frames to a provided `Surface`. No ADB knowledge.
- Produces:
  - `fun start(surface: Surface, width: Int, height: Int)` — configures `MediaFormat` `video/avc`, sets callback, starts.
  - `fun submit(bytes: ByteArray)` — enqueues into an available input buffer (buffers chunks until the codec provides an input index via callback).
  - `fun stop()` — flush/stop/release, idempotent.
  - `val firstFrameRendered: StateFlow<Boolean>` — flips true when the first output buffer is released to the surface (gate for enabling control).
- Errors: `MediaCodec.Callback.onError` -> expose via a `StateFlow<String?> error`; VM surfaces a friendly message and tears down.

**`data/tools/InputInjector.kt`** (~90 lines, PURE — fully unit-testable, NO device)
- Responsibility: build `input` shell command strings and map coordinates. This is the correctness-critical, testable core.
- Produces (pure functions):
  - `fun mapPoint(viewX: Float, viewY: Float, viewW: Int, viewH: Int, devW: Int, devH: Int): Pair<Int, Int>` — maps a view-space point to device-space, accounting for letterboxing (the SurfaceView uses `ContentScale.Fit`, so there may be bars; map only within the rendered content rect, clamp to device bounds).
  - `fun tapCommand(devX: Int, devY: Int): String` -> `"input tap <x> <y>"`.
  - `fun swipeCommand(x1: Int, y1: Int, x2: Int, y2: Int, durationMs: Int): String` -> `"input swipe <x1> <y1> <x2> <y2> <ms>"`.
  - `fun longPressCommand(devX: Int, devY: Int, durationMs: Int = 600): String` -> `input swipe` same point with duration.
  - `fun keyeventCommand(key: PortalKey): String` -> `"input keyevent <code>"` where `PortalKey` is an enum (BACK=4, HOME=3, RECENTS=187, POWER=26, VOLUME_UP=24, VOLUME_DOWN=25).
  - `fun textCommand(raw: String): String` -> `"input text <escaped>"` where escaping uses the existing `ShellQuote` plus `input text`'s space rule (spaces -> `%s`), and rejects/escapes characters unsafe for the shell.
- Consumes: existing `ShellQuote` (`data/ShellQuote.kt`).

**`viewmodel/MirrorViewModel.kt`** (~160 lines)
- Responsibility: orchestrate. Observe `ConnectionHolder.dadb`; on start, resolve size, start decoder, collect the mirror Flow into the decoder. Expose the `Surface` (via a callback the UI wires from its `SurfaceView`), `firstFrameRendered`, and an `error`/`unsupported` state. Forward control events by launching `shell()` calls. Retain the existing "save current still frame" action by reusing `ScreenCaptureManager` (one-shot PNG) on demand.
- State: `sealed class MirrorState { Idle; Starting; Streaming; Unsupported(msg); Error(msg); NotConnected }`.
- Re-entrancy: `mirrorJob: Job?` started synchronously; `start()` returns early if already active.
- `onDisconnected()`: cancel `mirrorJob`, `decoder.stop()`, reset to `NotConnected` (follows the standardized disconnect pattern).
- Carries over the existing 5-minute battery-warning threshold from `CaptureViewModel`.

**`ui/tools/mirror/MirrorScreen.kt`** (~200 lines)
- `AndroidView` hosting a `SurfaceView`; on surface created, hands the `Surface` to the VM. `pointerInput` detects tap / drag (swipe) / long-press and calls the VM with view-space coords + measured view size. Shows a spinner until `firstFrameRendered`. On `Unsupported`, shows a message + a button to fall back to the still-frame peek.
- Includes the `ControlBar` and a text-input entry (icon opens a `ModalBottomSheet` with a `TextField` + Send).

**`ui/tools/mirror/ControlBar.kt`** (~70 lines)
- A row of buttons: Back, Home, Recents, Power, Vol+, Vol- (text glyphs, no material-icons dep). Each calls `viewModel.sendKey(PortalKey.X)`.

### UI placement

The new Mirror screen **replaces** the current Capture/peek screen in the Tools tab. The old live PNG loop (`CaptureViewModel.toggleLive()` + `LIVE_INTERVAL_MS`) is retired. The still-frame "save current frame as PNG" action is preserved (reused inside the Mirror screen via `ScreenCaptureManager`).

Decision (not optional): `CaptureViewModel` is **deleted**; `MirrorViewModel` absorbs the one surviving responsibility — the on-demand still-frame save (`grabFrame()`/save-state) — reusing `ScreenCaptureManager` unchanged. The Tools tab navigation entry that pointed at the Capture screen now points at `MirrorScreen`. Any `CaptureSaveState`/`captureNotConnected` wiring in `MainScreen` + `MainScreenSnackbarEffects` is renamed to the Mirror VM's equivalents (no behavior change to the snackbar effects themselves).

### Error handling & edge cases

- **`screenrecord` unsupported / DRM / secure surface** (same failure class the current `screencap` code guards with `exitCode != 0`): `MirrorUnsupportedException` -> `MirrorState.Unsupported` -> message + fallback-to-peek button.
- **Decoder init/runtime failure** (odd resolution, codec quirk): `MediaCodec` error -> `MirrorState.Error` -> friendly message, clean teardown.
- **Disconnect mid-stream:** `onDisconnected()` cancels the job, closes the `AdbStream` in `finally`, releases the codec, resets state.
- **Resolution change / rotation:** re-query `wm size` on each stream (re)start; reconfigure the decoder if the size changed.
- **Control before first frame:** ignore input until `firstFrameRendered` is true.
- **Battery/heat:** reuse the existing 5-minute live-session warning.

### Testing

- **Unit (JUnit, no device) — the bulk of automated coverage:** `InputInjectorTest`
  - `mapPoint` scaling with no letterbox, with horizontal letterbox, with vertical letterbox, clamping at edges, exact corners.
  - `tapCommand` / `swipeCommand` / `longPressCommand` string format.
  - `keyeventCommand` for every `PortalKey` (correct keycodes).
  - `textCommand` escaping: spaces -> `%s`, quotes/special chars escaped via `ShellQuote`, empty string, unicode.
  - `wm size` parser: normal, "Override size" line present, malformed -> sensible fallback.
- **Manual E2E** on Samsung `TEST_PHONE_SERIAL` connected to Portal `FAMILY_PORTAL_SERIAL`: latency feel, tap accuracy across the frame, swipe/scroll, long-press context menu, each hardware key, text entry into a Portal field, transparent restart across the 180s boundary, disconnect cleanup (no leaked stream/codec).
- `ScreenMirrorManager` and `H264Decoder` are validated manually (not unit-testable without a device/codec).

## Feature 2 — Screensaver photo-count guidance hint

### Background (root cause, verified on device)

The Portal's slideshow is driven by its **own firmware** (`com.immortal.launcher/PhotoDreamService`, "Superframe"), not by Portal Toolkit. Device inspection (read-only) confirmed: 7 files in `/sdcard/Pictures/PortalInstaller`, all with distinct md5 hashes; 7 unique MediaStore rows; no app code that pads/repeats images. The "same image shown 5 times" is the firmware re-cycling a small photo set — behavior the app cannot control (no reachable display setting over ADB shell). The only real lever is a larger unique-photo set.

### Change

A single guidance line on the Screensaver tab, placed just after the existing storage-summary line (`ScreensaverTab.kt` around line 143, after `state.folderBytes`/`state.deviceFreeBytes`). It uses the already-available `state.contents.size` (the unique file count).

- When `state.contents.size in 1 until RECOMMENDED_MIN`: show a hint, e.g. *"N photos. The Portal repeats small sets — add about M more for a varied slideshow."* (`RECOMMENDED_MIN = 20`, defined as a constant, not hardcoded inline).
- When `state.contents.size >= RECOMMENDED_MIN`: show nothing (or a subtle "N photos" count — no nag).
- When `0`: the existing empty-state text already covers it; no hint.

Purely additive, informational, no behavior change to upload/dedup. This corrects the expectation honestly rather than pretending the app controls the loop.

### Testing

- **Unit:** a small pure helper `fun screensaverHint(count: Int, recommendedMin: Int): HintLevel` returning `None` / `AddMore(needed)` / `Ok`, tested at boundaries (0, 1, RECOMMENDED_MIN - 1, RECOMMENDED_MIN, above).
- **Manual:** confirm the line appears with the current 7-photo set and disappears once the count is raised past the threshold.

## Scope boundaries (YAGNI)

- **No** save-to-MP4 recording (deferred to a possible v1.6).
- **No** audio (Portal is Android 10; ADB audio forwarding needs Android 11+).
- **No** multi-Portal / clone-sync in this release (separate future spec).
- **No** camera stream / intercom (infeasible in a controller-only, shell-only architecture).
- The Screensaver hint does **not** attempt to control firmware repetition — it only informs.
