# Portal Toolkit v1.2 → v1.4 Roadmap — Design Spec

**Date:** 2026-08-01
**Status:** Approved scope — all 11 roadmap features, phased across three releases.
**Mockups:** `docs/mockups/improvements-roadmap.html` (features #1–#11)

## Goal

Take Portal Toolkit from a capable v1.1.0 utility to a complete Portal
management suite: solid foundations, power tools (shell/logcat/screen),
and full two-way file + screensaver photo management. Every feature card
in the mockup page ships; nothing is thinned.

## Context (v1.1.0 baseline)

- Kotlin + Jetpack Compose, single module, ~6.7k LOC.
- ADB via `dev.mobile:dadb:1.2.6` (pure Kotlin, no adb binary).
- Portal devices run Android 10 / SDK 29 (`PortalDeviceConfig.MAX_SDK`).
- Known debt: `ui/MainScreen.kt` is a 3,659-line monolith; a 953-line
  god-ViewModel; reflection into dadb private internals in
  `PortalDiscoveryManager` and `UsbAdbBridge`; UI writes SharedPreferences
  directly; zero tests; light-only hardcoded theme; old Compose BOM
  (2023.10.01) / compileSdk 34.

## Phasing & rationale

Dependency-ordered: Phase 1 makes the codebase safe to extend, Phase 2
adds the Tools tab, Phase 3 builds the file layer and everything on it.
Each phase = its own implementation plan, tests, commit-per-feature,
release notes.

## Phase 1 — v1.2 "Feels solid"

### 10a. Split MainScreen.kt (mechanical, zero behavior change)

`ui/MainScreen.kt` (3,659 lines) → ~14 focused files:

- `ui/theme/Theme.kt`, `ui/theme/Color.kt` — palette moves out of MainActivity
- `ui/common/` — SectionCard, status chips, confirm dialogs, shared shapes
- `ui/devices/` — DevicesTab, ConnectionSection, SavedPortalsCard,
  OsUpdateBlockCard, BackupCard, WirelessAdbGuideTab, scanner + rename dialogs
- `ui/apps/` — AppsHubTab, InstalledAppsTab, PortalAppsTab, ProfilesTab,
  profile editor dialog
- `ui/photos/` — PhotosTab (replaced in Phase 3)
- `ui/more/` — MoreTab, HistoryTab, SettingsTab

Delete dead `WirelessAdbTab` (defined, never called). Update Compose BOM
and compileSdk 34 → 35 first, fix any deprecations.

**Verify:** clean build + manual pass through every screen/dialog.

### 10b. Navigation-Compose

Replace `selectedTab: mutableIntStateOf` with Navigation-Compose routes
for the 4 top-level destinations. Sub-tab selection preserved via
`rememberSaveable`. Back button navigates tab back-stack.

### 10c. Remove dadb reflection (silent-breakage time bomb)

Both `PortalDiscoveryManager` (reflects `AdbConnection.Companion.connect`)
and `UsbAdbBridge` (reflects `connect$default`) get replaced by a small
vendored transport module `data/adb/` implementing the ADB
connect-over-arbitrary-stream handshake ourselves (protocol is stable and
small), with unit tests. No behavior change; dadb stays for everything else.

### 10d. ViewModel split + persistence hygiene

- `PortalViewModel` (953 lines) → `ConnectionViewModel` (connect, USB,
  discovery, wireless ADB, OTA, device status), `AppsViewModel` (install,
  uninstall, profiles, portal app list), `BackupViewModel`,
  `PhotosViewModel`. Shared `Dadb` session owned by a `ConnectionHolder`
  injected into managers.
- History persistence moves from MainScreen SharedPreferences code into
  `data/HistoryStore`.
- SharedPreferences (saved portals, profiles, history) → Jetpack DataStore
  with one-time migration.

### #7. Connection health + auto-reconnect

- Heartbeat coroutine: `shell:echo ok` every 20 s while connected.
- On failure: state → `Reconnecting(attempt, nextRetryIn)`; exponential
  backoff 2 s → 30 s cap; retry saved host/port. Success → toast
  "Reconnected"; user can cancel to `Disconnected`.
- Persistent connection status chip in the top app bar of every screen
  (green Connected / amber Reconnecting / neutral Disconnected).
- Connection log (last ~50 events, in-memory) viewable from the Devices tab.

### #5. Device dashboard + power controls

- Dashboard card on Devices tab: storage + RAM gauges (donut), uptime,
  Android/SDK, OTA-block status, wireless-ADB state. Data from existing
  `getDeviceStatus()`; add uptime (`/proc/uptime`) and temp if exposed
  (`dumpsys thermalservice`, gracefully absent otherwise).
- Controls: Reboot (`shell:reboot`), Reboot to recovery
  (`shell:reboot recovery`), Screen off/on (`input keyevent 223/224`),
  Launch app (picker over installed portal apps →
  `monkey -p <pkg> -c android.intent.category.LAUNCHER 1`).
- Reboot/recovery behind confirm dialogs.

### #9. Dark theme + dynamic color

- `darkColorScheme` (teal-on-dark: primary `#4FD8D4`, background `#131615`).
- Setting in existing Settings tab: System (default) / Light / Dark,
  persisted in DataStore.
- `dynamicLightColorScheme`/`dynamicDarkColorScheme` on Android 12+,
  behind a "Use system colors" toggle (off by default to keep brand teal).

### Phase 1 tests (first in repo)

Backup manifest validation, zip-slip guard, minSdk gate, reconnect
backoff schedule, vendored ADB transport handshake, DataStore migration.

## Phase 2 — v1.3 "Power tools"

New **Tools** bottom-nav destination (replaces "More"; History/Settings
move under Tools alongside the new tools, keeping 4 tabs total).

### #1. Remote shell

- Transcript UI (LazyColumn), monospace, copyable output; input field with
  send; command history (DataStore, last 100, up/down recall).
- Quick-command chips (editable defaults: `pm list packages -3`,
  `getprop`, `wm size`, `df -h`).
- Destructive-command guard: regex classifier (`rm -rf`, `reboot`,
  `pm disable`, `pm uninstall`, `settings put`, writes outside /sdcard)
  → confirm dialog before run. Classifier unit-tested.
- Each command runs via `dadb.shell()`; long-running commands show a
  spinner and can be cancelled (connection-level close, then reconnect).

### #2. Live logcat viewer

- Stream `shell:logcat -v brief` via `dadb.open()`; parse into
  `LogLine(level, tag, message)`.
- Ring buffer of 2,000 lines (memory-flat); auto-scroll with pause on
  user scroll-up.
- Filters: level chips (All/E/W/I/D), package/tag text filter
  (client-side), Errors-only mode restarts stream as `logcat *:E`.
- Pause/resume; Export writes visible buffer to a share-able text file.
- Crash detection: `FATAL EXCEPTION` lines trigger a snackbar with
  "Jump" scrolling to the crash.

### #4. Screen capture & live peek

- Screenshot: `screencap -p /sdcard/.pt_peek.png` → `dadb.pull()` →
  decode → display + save to phone Pictures/PortalToolkit via MediaStore.
- Live peek: repeat loop while toggled, ~1.5 s interval, skip frame if
  previous still transferring; battery note shown after 5 min.
- Stretch (attempted last, cut if problematic): tap mode mapping image
  taps to `input tap x y` scaled to device resolution from `wm size`.

### Phase 2 tests

Logcat line parser (golden lines incl. multiline stack traces), ring
buffer eviction, destructive-command classifier, quick-chip persistence.

## Phase 3 — v1.4 "Complete manager"

### #3. Two-way file manager (foundation)

- `data/PortalFileManager`:
  - `listDirectory(path)` → parse `ls -la` (toybox format, SDK 29 stable)
    into `RemoteFile(name, path, isDirectory, isSymlink, sizeBytes,
    modifiedAt, permissions)`.
  - `pull`, `push` (dadb sync protocol; counting-Source byte progress),
    `delete`, `move`, `copy`, `rename`, `mkdir`.
  - Path-safety guard: operations outside `/sdcard` require the
    "Advanced mode" toggle (per-session, off by default).
- `viewmodel/FileManagerViewModel`: `FileBrowserState` (path stack,
  entries, selection), `TransferState` (queue, per-file progress,
  cancellable Jobs).
- Files screen under Tools: breadcrumbs, type-icon rows (dir/image/file),
  sort by name/size/date, long-press multi-select, actions
  pull/push/delete/move/rename/new-folder; delete confirms with count +
  total size; directory delete only when empty in v1 (explicit design cut).
- Partial-push cleanup: failed/cancelled push deletes the incomplete
  remote file.

### #11. Screensaver manager (photo-first specialization; replaces Photos tab)

- Folder selection: `findImageFolders()` scans
  `find /sdcard -maxdepth 3 -type d`, counts image extensions per dir,
  ranks suggestions; legacy `/sdcard/Pictures/PortalInstaller` always
  listed; "Browse all folders…" opens the Files picker. Choice persisted
  per device (`SavedPortalStore` gains `screensaverFolder`).
- Manage view: header (folder + Change), storage meter (folder bytes vs
  device free), thumbnail grid of device contents, multi-select →
  Delete / Move to… / Pull to phone; rename via row menu.
- Thumbnails: pull image once, downscale (`inSampleSize` to ~256 px),
  disk LRU cache keyed by `path + mtime + size`, capped 100 MB.
- Upload: photo picker → dedupe check (name + byte size match against
  folder listing; duplicates skipped by default, override per file) →
  queued transfer with per-file progress, Cancel, and post-upload summary
  (uploaded/skipped/failed counts). MediaScanner broadcast after upload.
- The old PhotosTab is deleted; its route redirects here.

### #6. Rich portal app list

- Label + icon: `PackageManager.getPackageArchiveInfo` needs a complete
  APK file (partial pulls are not reliable), so pull each app's full
  `base.apk` once over Wi-Fi, extract label + icon, cache both to disk
  keyed by `package + versionCode`, then delete the temp APK. The cache
  makes this a one-time cost per app version.
- List shows icon, label, version, size; sort chips (name/size).
- Per-app actions: Launch (monkey), Force stop (`am force-stop`),
  Clear data (`pm clear`, confirm dialog), Uninstall (existing flow).

### #8. Real progress + cancel (cross-cutting retrofit)

- Counting-Source progress on every push/pull: APK install, photo/file
  upload, backup, restore, thumbnail pulls.
- Install screen: step list (verify → push base → push splits → commit)
  with byte progress + speed + ETA.
- Every long operation holds its `Job`; Cancel buttons on install,
  upload, backup, restore, scan, profile apply.
- Batch states carry per-item results:
  `ProfileApplyState.Done(succeeded: List, failed: List<(pkg, reason)>)`
  — fixes profile apply reporting Success despite failures; photo/file
  uploads and restores likewise report per-item outcomes.

### Phase 3 tests

`ls -la` parser goldens (files, dirs, symlinks, spaces in names), dedupe
matcher, path-safety guard, thumbnail cache keying/eviction, icon cache
keying, per-item batch state transitions.

## Cross-cutting rules

- **Errors:** every remote op flows through the existing `AdbError`
  hierarchy + `formatAdbReason`; batch ops always surface per-item
  outcomes; no silent swallowing.
- **Immutability:** state objects are immutable data classes; StateFlow
  updates create new instances.
- **Workflow:** conventional commits, commit-per-feature within a phase,
  tests written before each commit, release notes per phase
  (`RELEASE_NOTES_v1.2.0.md` etc.). No AI attribution in commits or code.
- **Strings:** all user-facing text in `strings.xml` (ro default + en),
  matching the existing i18n setup.

## Out of scope (explicit)

Full scrcpy-style video mirroring, backup encryption/scheduling,
Android 11+ pairing codes, md5-based dedupe (name+size only), file
search, zip/unzip in file manager, recursive directory delete, iOS/web.

## Risks

- **`ls -la` parsing** — toybox output on SDK 29 is stable; goldens from a
  real Portal Mini before building the parser (user has device access).
- **Vendored ADB transport (10c)** — the one genuinely tricky piece;
  mitigated by tests against dadb's own connection as reference behavior.
- **Icon extraction cost** — full-APK pull per app version; acceptable
  one-time cost on Wi-Fi, cached forever after.
- **MainScreen split regressions** — no tests exist before Phase 1;
  mitigation is the mechanical-only rule plus a full manual pass.
